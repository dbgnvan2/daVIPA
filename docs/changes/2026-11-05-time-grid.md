## Summary

The Plan screen no longer plans a day as an **order**. Every half hour from Day
Start to Day End is a box, drawn whether it holds anything or not, and a block
stores **which box** it is in (`time_blocks.slot_index`) relative to Day Start.
The clock times follow from the box on read.

Three decisions settled by Dave before the build, and the model is them:

1. **Fixed grid, drop on a box.** Gaps are a legitimate day. Nothing ever
   slides up to close one.
2. **Odd lengths round up.** A 45-minute task occupies two boxes, keeps its own
   45 minutes (it ends 09:45), and the second box says `15m spare`.
3. **A box is worth 30 minutes however many tasks are in it** — up to four.

What that buys, and the reason the change was worth making rather than
patching the order model:

- **A Day Start change writes nothing.** `slot_index` is relative to Day Start,
  so moving it re-times every planned day on every date by writing zero rows.
  This is what retired `repack_all_days`, the "this day is too full to re-time"
  refusal, and the transaction that could leave one day derived from one set of
  bounds and another from a different set.
- **A move is an assignment, not a shuffle.** A drag writes one row's box. It
  retired `reorder_time_blocks`, `move_block`, `move_block_to_gap`,
  `sort_blocks` and `renumber`.
- **`span` is derived, never stored.** `ceil(planned_minutes / 30)`. Two columns
  that can disagree is P6.
- **`slot_index` is nullable with no default.** `NULL` means "never placed",
  which is a different fact from "box 0". A default of 0 would have piled every
  unplaced block onto 08:00.

Work the grid cannot hold is **surfaced, never dropped** (P2): a block whose box
is past a Day End moved earlier, whose length now runs off the end, that lunch
has since moved onto, or that has never been placed, is drawn in an *Outside the
day (n)* group under the grid, and dragging it onto a box places it. Days
planned under the old model are adopted on first open: a **readable start time
goes on the box that time names or nowhere**, never slid to the nearest free
box, because that would move planned work to an hour nobody picked.

Every refusal names itself — outside the day, running into lunch, that half hour
full — and writes nothing. A release in the day column but on no box creates
nothing and says *Drop an item on a half-hour box*: the app does not choose an
hour.

**TG-M8.3 was dropped, not implemented.** The sliver bug the step was ordered
for **does not reproduce**: `test_tgm81`/`test_tgm82` passed against unmodified
code, and a probe measured a row at 667px inside a 671px pane in the real Plan
screen. The rationale was false too — `_aim_pointer_at`'s `max(1, w // 2)`
alters the aim only at widths 0 and 1. No fix was written and none is claimed.
The two width tests were kept and moved onto the grid pane, because the property
they pin had no coverage at all: every other geometry test asserts *behaviour*,
and a row collapsed to a sliver satisfies all of them.
