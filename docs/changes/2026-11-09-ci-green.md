## Summary

CI has been red on nine tests on all three Python versions since at least
`3f705b4`. Run 42586742228 at `1eb6ef4` reports `9 failed, 2646 passed,
2 skipped`; run 42574953009 at `a2c3124` reports the same nine names, so the
SST batch caused none of them. This batch rewrites all nine.

Seven of them set a window attribute and read it back. On a desktop a window
manager honours the write; CI runs under `xvfb-run -a`, which has no window
manager, so the read-back reported the display as a code fault. They now ask
one shared precondition, `tests/display_capabilities.py`, which builds a real
window, asks the display, caches the answer for the run, and **skips with a
reason naming the attribute** where the capability is missing. Six of the seven
had no precondition at all; the seventh had a private copy nobody else could
use, which is why six stayed red after `23f0cc7` fixed one.

The remaining two are not that family:

- `test_updm14_zero_width_body_is_a_noop` passed locally and failed on CI with
  `assert 1208 <= 8` — `body.configure(width=8)` shrinks the body here and did
  nothing under X11, so the test failed before reaching the code it names. It
  now stubs `body.winfo_width`, which is the one number
  `split_panel.py` reads, and keeps the precondition assertion against the
  stub. Two earlier attempts to force the real resize were withdrawn after
  measurement (see Risks).
- `test_pbm61_a_tall_row_keeps_its_two_lines_together` could not be reproduced
  on a working machine at all: it is one of the 22 that
  `GETMOREDONE_NO_MAPPED_WINDOWS=1` skips. Its floor assertion was satisfied by
  the very layout it was written to reject — measured: in the broken state the
  title sits at y=100 in a 274px row, which leaves 154px below it and passes
  `below >= height // 2`. Rewritten to assert the **bottom** of the text, and
  renamed `test_pbm61_a_tall_row_keeps_its_slack_below_its_text`, because
  PD-M1 moved the length onto the task's one line and the old name described a
  two-line row that no longer exists. Repo test rule (b) and (c), stated in the
  docstring.

The plan was written, measured against the repo, and then put through one cold
pass, which found six defects in it. Two of them falsified the plan's own
premise and are corrected in the plan rather than quietly dropped: **Xvfb does
report `-alpha` back**, for a window that has been mapped — two sibling tests
in the same file prove it on CI — so the question the probe asks is the
narrower "does a *withdrawn* window report the attribute back"; and skipping
the two `-alpha` tests **does** cost coverage, because one of them is the only
test in the suite that drives a raw `tk.Tk` and `tk.Toplevel` through the
window-hiding guard. Its display-independent assertions are now made before the
precondition, so they still run on CI.

## Risks / Known gaps

- **CIG-M2's cause is still unknown.** Why `configure(width=...)` does not move
  `winfo_width()` under X11 is undiagnosed. The test no longer depends on the
  answer — it forces the reading the code takes — but a comment asserting a
  cause nobody measured is the defect this batch is about, so the question is
  filed as `CIG-A8` rather than answered. Two such comments were written and
  withdrawn here: a fixed-width holder (the body reports 1px whatever the
  holder does) and the root's `wm geometry` (`_root()` sets 1400x900, and 1208
  is the body's own request).
- **A skip is less coverage than a pass.** Seven assertions no longer run on
  CI. That is honest rather than new — they were measuring Xvfb — but two of
  them need not skip at all (`CIG-A2`) and two more are testable with a spy
  (`CIG-A3`).
- **The registry is not a detector.** `CIG-M1.4` catches a precondition dropped
  from one of the eight known callers. It cannot catch a *new* test written the
  way these seven were. `CIG-A1`.
- Nothing asserts the skip count, which will be 10 on CI after this batch. A
  count nobody checks is how the test figures in `CLAUDE.md` drifted by 741 and
  13. Also `CIG-A1`.
