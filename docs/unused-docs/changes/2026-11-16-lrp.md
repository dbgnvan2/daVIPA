## The measurement behind min_one_row_px()

`fit()` first sized the filters and then asked `one_row_px()` whether one row
fits. Both numbers depended on the filters' drawn widths, so each fit changed
the input to the next one. All Items measured 997 px, then 916, then 922 for
the same toolbar, and a toolbar that had wrapped never unwrapped — the test
that caught it passed for the wrong reason until the numbers were printed.

`one_row_px()` now counts a filter at its **default** width and
`min_one_row_px()` at `FILTER_MIN_PX`; neither moves as the filters resize,
and `test_lrpm11_the_threshold_does_not_move_as_the_filters_resize` holds it
at four widths.

## The sweep found a red test, and this batch had not run it

`tests/test_ui_presence.py` — the repo's screen contract — still asserted the
six removed buttons existed, and it reaches those lines. The batch had run
every resize suite and every Project Board suite in the plan's verification
list, and none of them was that file. Confirmed red by stashing the fix and
re-running. The lesson is about which files a removal touches, not about the
removal: the next batch that deletes a widget should grep the test tree for
its attribute name before trusting a targeted run.

The other nine findings and what was done about each are tabled in the plan.
Two mattered beyond their own fix: raising
`AppSettings.drag_schedule_title_col_width` to reach the Scheduler was the
wrong lever (it is the Plan screen's live title width, and a saved settings
file overrides it anyway), and `week_actions.WeekTacticActionsPanel` is an
eighth listing of action items that the conformance file did not name.

## Walk checklist (on the running app)

The app holds a lock: quit `/Applications/daVIPA.app` before launching from
source, or the source launch exits silently.

1. **The shared defaults.** A stored column weight wins over a default, so
   on this install most lists will open at the shape already dragged. To see
   LRP-M6, back up
   `~/Library/Application Support/GetMoreDone/settings.json` and delete its
   `*_col_widths` entries (and `drag_schedule_title_col_width`), or test on a
   fresh profile. Then open Today, Upcoming, All Items,
   Hierarchical, Completed, a project's Action Items and the Scheduler: the
   same column kind should be the same width on every one, and the Scheduler
   should open with Title wider (260, not 220) and its lineage columns
   narrower (150, not 170).
2. **Proportional resize.** On each of the seven, drag the window narrower
   and wider. Every text column should move together, none narrower than six
   characters, and the heading row should stay over its column.
3. **The maxima.** On the widest window the display allows, the Scheduler's
   lineage columns should stop growing (800 px) where they used to keep
   going. Title stops at 2000.
4. **The row font.** Settings → list row font, larger. Every floor widens,
   the Scheduler's included. (Its *text* clamp does not follow the setting —
   that is LRP-A2, filed, not fixed.)
5. **The filters, narrowing.** On All Items, drag the window narrower and
   watch the order: the search box gives up width first, then Status and Who
   shrink together with Who staying the wider of the two, down to about
   90 px each; only then do the right-hand buttons move to a second row.
6. **The filters, widening.** Widen again: the filters grow back and stop at
   twice their starting width rather than becoming banners, and the second
   row folds back into one row with the controls in their original order.
7. **Left-justified.** The second row's controls should start at the
   toolbar's left edge and read left to right.
8. **Completed and the Scheduler.** Completed's Who filter is in the group
   that wraps — check it both resizes and wraps. The Scheduler's four
   filters (Who, Segment, SubSegment, Project) should resize together.
9. **The Project Board's right panel.** Select a project: the toolbar above
   Action Items should hold **Bulk Edit** and, on a project that is not
   Active, **Set Active** — nothing else. With no items linked, the empty
   state should read "Open an action item and set its Project to file it
   here"; with no notes, "Use the note icon on the project's tile".
10. **The removed routes still work.** The tile's pencil opens the project
    editor; its 📄 icon offers Create / Link note; each note row has its own
    **Open**.
11. **The route that replaced two buttons.** Create an item on Today, set its
    **Project** in the item editor, and confirm it appears in that board's
    Action Items list.
12. **`app.log`.** After all of the above, check it holds no traceback.
